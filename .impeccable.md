## Design Context

### Users
Non-technical Scaler learners practice building n8n workflows, while case authors assemble realistic node sets for new learning simulations. The interface must make node identity and purpose recognizable at a glance.

### Brand Personality
Faithful, confident, instructional. It should feel like a polished n8n authoring environment expressed through Scaler's Syntax design system, never like a generic workflow mockup.

### Aesthetic Direction
Use the established light Syntax by Scaler tokens and the restrained n8n canvas language. Product and provider nodes use their real brand marks; generic workflow, data, and control nodes use one consistent Phosphor icon family. Icons sit on calm neutral chips, retain their natural brand colors, and remain legible at 16–38px.

### Design Principles
1. Prefer semantic recognition over decoration: one node purpose, one unmistakable icon.
2. Use official brand marks for products and providers; use Phosphor for generic concepts.
3. Preserve n8n's visual meaning while keeping spacing, contrast, and interaction aligned with Syntax.
4. Never expose implementation details such as locked APIs or simulation constraints through noisy icon styling.
5. Keep every icon accessible, theme-safe, and readable in the picker, canvas, and detail view.
